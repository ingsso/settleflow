## 2. 핵심 설계 판단 — "무엇을, 왜"

| 판단 | 근거 한 줄 | 출처 |
|---|---|---|
| **되돌아오는 축을 행으로 내린다** | 계획서 전이표(`ACTIVE→PAST_DUE→CANCELED`)는 ABA 가 생겨 멱등 backbone 이 죽는다 → 주기를 `billing_cycle` 행으로 | W5D1 |
| 계약과 건강도를 **갈라지기 전에** 분리 | 한 축이 둘을 겸하면 나중에 갈린다(W3D4·W3D5·W4D5 에 이은 **네 번째**) | W5D1 |
| `payment` 를 **시도 층**으로 | 구독 청구는 주문이 없다 → `order_id` 널 허용 + **배타적 아크**. 한 주기에 시도가 여럿 | W5D1 |
| ★ **폴링 + 리스(CAS)** — Quartz 폐기 | 기술결정서의 두 근거 중 하나는 `next_retry_at` 이 이미 충족했고, 남은 하나를 위해 Quartz 를 얹으면 *"다음 시도는 언제인가"* 의 원천이 **둘**이 된다 | W5D2 |
| **낙관적 락으로는 못 막는다** | 폴링은 [부수효과 → 판정] 순서라 둘 다 PG 를 부른 뒤 하나가 롤백된다 — **롤백은 우리 DB 만 되돌린다.** 락이 약해진 게 아니라 **순서가 뒤집혔다** | W5D2 |
| 상한을 **값으로 안 적는다** | `maxAttempts=3` 은 `[1,3,7]` 과 항상 같아야 하는 값의 복제다. **포기는 목록에 다음 칸이 없다는 사실** | W5D2 |
| 폴러가 **둘**(P1 날짜축 / P2 시각축) | 축이 다르다. 하나로 합치면 한 쿼리가 두 질문을 겸한다. **둘이 같은 주기를 노리지 않게** `PENDING`/`FAILED` 로 가른다 | W5D2 |
| ★ **계기를 우리 DB 에서 PG 호출 수로** | *"한 시도 = 한 PG 호출"* 은 **검증 대상 코드 자신의 성질**이라 `payment` 행을 "청구 횟수"라 부를 수 없다 | W5D3 |
| 계획서 D3 의 **전제를 반증** | 멱등키는 *"같은 시도의 재전송"* 을 지키는 물건이고, 재집기가 만든 두 시도는 PG 에겐 **서로 다른 정당한 청구**다 | W5D3 |
| ★ **미결 시도는 새 청구가 아니라 재전송** | `PENDING`·`UNKNOWN` 은 *"돈이 움직였는지 모른다"* — 되돌릴 근거가 없으면 **새로 낼 근거도 없다**(`markUnknown` 의 반대 방향, 같은 규칙) | W5D4 |
| 재전송에 **상한을 안 건다** | 상한은 *"청구를 몇 번 걸었나"* 를 세는데 재전송은 청구를 안 늘린다. **무한 질의는 무한 청구와 다르다** | W5D4 |
| 대신 **조용하면 안 된다** | 멈추는 장치가 없으니 **드러나는 장치**가 필요하다 → 6시간 넘은 미결을 센다 | W5D4 |
| ★ **차단기가 미결 시도를 확정하면 안 된다** | W4D1 의 *"안 보냈으니 확실한 앎"* 은 **새 시도에만** 참이다 — 재전송이 안 나간 건 원래 요청에 대해 아무것도 안 알려준다 | W5D4 |
| 두 종류의 단언을 **파일 안에서 가른다** | *"우리가 보증하는 것"*(키 개수)과 *"PG 에 기대는 것"*(같은 키면 한 번 과금)은 성질이 다르다 — 후자는 스텁 위의 `[실측·가정]` | W5D4 |
| **헤드라인은 키 개수, 교차검증은 PG 호출 수** | 키만 보면 우리 DB 안에서 자족하고, 호출 수만 보면 **재전송과 중복 청구를 못 가른다** | W5D5 |
| 백스톱 계기를 **프로덕션 밖에서** 얻는다 | `abandon` 의 로그는 집기 직전 판정에서만 찍힌다 → 코드를 안 바꾸고 발화 횟수를 센다(W4D1 데코레이터와 같은 계열) | W5D5 |
| ★ **전제의 회귀는 테스트로 못 막는다** | 백스톱은 *어떤 시나리오*가 아니라 *"미결을 재전송으로 흡수한다"는 전제가 사라지는 것*을 지킨다 → **주석이 그 자리를 대신한다** | W5D5 |
| ★ **k6 는 시나리오 ③ 의 부하 발생기가 아니다** | Dunning 은 폴링으로 스스로 깨어나 밖에서 쏠 곳이 없다. 트리거를 HTTP 로 열면 **프로덕션에 없는 모양**을 재게 된다 → 부하원은 **인스턴스 다중화** | W5D5 |

## 4. 반복된 패턴 (회고에서 뽑을 결)

### ★ 4-1. "전제가 만료됐다" 가 사흘 연속 났다 — 이번 주의 결

| | 어제까지 참이던 것 | 무엇이 정의역을 뺏었나 | 어디서 드러났나 |
|---|---|---|---|
| D3 | `countConcludedAttempts` **+1** | **웹훅이 두 번째 호출부**가 됐다 — 시도가 이미 `UNKNOWN` 이면 이미 세어지는 쪽에 있다 | 사다리가 한 칸 짧아짐 |
| D4 | 차단기 개방 = *"안 보냈으니 확실한 앎"*(W4D1) | **재전송이 생겼다** — 안 나간 재전송은 원래 요청에 대해 아무 말도 안 한다 | `PENDING` 이어야 할 자리에 `FAILED` |
| D5 | 백스톱 = *"마지막 벽"*(W5D4) | **재전송 분기가 그 앞에 놓였다** | 세 경로 전부 발화 0회 |

**셋 다 버그를 넣은 게 아니다.** 새 호출부·새 분기가 들어오면서 **기존 판단의 정의역이
조용히 좁아졌다.** 그리고 셋 다 **같은 사람이 같은 주에 만든 변경**이 원인이다 — D4 의
차단기 문제는 D4 의 재전송이, D5 의 백스톱 문제는 D4 의 재전송이 만들었다.

> 이건 W4 회고 4-1(*"검증 없이 적힌 단정이 다음 세션의 설계 전제가 된다"*)의 **다음 판**이다.
> 그때는 *검증을 안 한 것*이 문제였고, 이번엔 **검증했고 참이었던 것**이 문제다.
> 참이었던 문장은 의심 대상이 안 되기 때문에 더 오래 산다.

### ★ 4-2. 같은 수치를 세 번 다르게 셌다 — 계기의 이동

```
W5D2   payment 행 수         "동시 폴링 10개 → 청구 1회"        ← 틀렸다(D3 이 정정)
W5D3   PG approve 호출 수    "크래시 후 재집기 → 3회"            ← 계기를 바깥으로 옮김
W5D4   서로 다른 키 개수      "키 3개 → 2개, 호출은 그대로 3회"   ← 호출로도 부족했다
```

**한 번에 안 맞은 게 아니라 두 번 갈아탔다.** D3 의 교체는 *"대리 지표의 근거가 검증 대상
코드 자신의 성질"* 이라서였고, D4 의 분화는 **재전송이 호출을 늘리면서 키를 안 늘려서**다.

지금 규약은 **둘을 나란히 두는 것**이고, 그 사이의 차이에 이름이 붙었다:

```
PG 호출 − 키 개수 = 재전송 횟수        [실측] D5 대조군 A 에서 19 − 10 = 9
```

### 4-3. 계획서/기술결정서 폐기 — 8주 연속

전이표(D1) → **Quartz**(D2) → D3 의 전제 자체(D3) → **k6 의 역할**(D5).

D3 은 성질이 다르다 — **대안을 낸 게 아니라 *"도구가 문제를 안 겨눈다"* 로 끝났다.** 그리고
그 결론이 D4 에서 **한 칸 좁혀졌다**(*"멱등키가 못 겨눈다"* → *"재전송해야 할 자리에서 새
시도를 만들었다"*). 폐기 자체가 다음 날 정정 대상이 된 첫 사례다.

### 4-4. 재는 자와 재이는 것 — W4 회고 4-2 의 계승

- **D2**: 스위트가 물려준 게 데이터가 아니라 **회로**였다(거짓 red 1회) → 회로 리셋을 베이스로
- **D3**: 계기가 검증 대상 코드의 성질에 기대고 있었다 → PG 호출 수로
- **D4 오류 ③**: 새 계기(멱등 스텁)를 만들어놓고 **그 계기가 겨눌 상황을 안 만들었다** —
  통과하는데 겨누는 게 없는 테스트
- **D5**: 백스톱 계기를 **프로덕션 코드 밖**(로그)에서 얻어 이 함정을 피했다

### 4-5. 값은 어긋난 칸에서 나왔다 — 6번째

D3(off-by-one 이 계기 교체에서 딸려 나옴) · D4(차단기 상호작용은 테스트가 `FAILED` 를 내서
드러남) · **D5(대조군 A 의 크기 예측 2~4 가 빗나가 10 이 나왔고, 그 반증이 *"직렬화는 공짜로
얻고 있었고 CAS 는 승자를 가릴 뿐"* 을 끌어냈다)**.

**D5 의 것이 이 계열에서 가장 깨끗하다** — 예측을 먼저 적고 *"10 이 나오면 내 모델이 틀린
것"* 이라는 반증 조건까지 같이 적어둔 덕에, 나온 수가 **모델을 반증하는 수**로 읽혔다.

### 4-7. Claude 가 선택지를 좁게 냈다 — 이틀 연속, 모양이 다르다

| | 무엇을 | 결과 |
|---|---|---|
| **D4 ①** | 선택지를 **둘**로 단정(*"한쪽을 고치면 다른 쪽이 깨진다"*) | **세 번째(재전송)를 못 봤다.** 그 단정이 D3 문서의 결론을 한 칸 넓혀 **이틀치 문서를 고쳐야 했다** |
| **D5 ①** | 선택지 셋을 **"k6 가 부하를 준다"는 공통 전제** 위에 짬 | 사용자가 고른 뒤 그 전제가 무너졌다. **선택지의 폭이 아니라 바닥이 좁았다** |

둘 다 *"틀린 사실"* 이 아니라 **선택 가능한 범위를 줄인 것**이라, 사용자가 그 안에서 아무리
잘 골라도 밖으로 못 나간다. **D5 에서 사용자가 *"모르겠어"* 라고 답한 것도 이 자리다** —
선택지가 나오기 전에는 설계 유도가 성립하지 않았다.

### 4-8. 프로덕션 코드를 안 고치고 끝낸 날이 처음 나왔다

D5 는 `feat:` 커밋이 없다(실행 코드 무변경, 주석만 추가). 겨눈 셋이 전부 **이미 있는 코드**였고
없던 것은 **그것을 보는 눈**이었다. W4D3(k6 설계, 프로덕션 무변경)과 같은 계열이지만, 그때는
새 산출물(스크립트)을 만들었고 **D5 는 기존 코드에 계기만 붙였다.**
