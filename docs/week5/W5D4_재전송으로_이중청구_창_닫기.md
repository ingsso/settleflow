## 1. 오늘의 범위 — 계획서 D4 를 미루고 D3 의 빚을 갚았다

계획서 D4 는 차단기 연동이다. 안 했다. **W5D3 이 *"이중 청구 창을 안 닫았다"* 로 끝났고
(D3 이월 1), 그걸 하루 더 들고 가는 게 더 나쁘다고 봤다.**

차단기를 아예 안 건드린 건 아니다 — 재전송을 넣다가 **차단기가 미결 시도를 확정해버리는
자리**가 드러나 그건 고쳤다(§6). 계획서가 요구한 *"OPEN 이면 재시도 스킵, 다음 주기로 연기"*
는 여전히 미착수다(§11 이월 1).

## 3. 세 번째 선택지 — 재전송

W5D3 §7 은 이렇게 끝났다:

> *"같은 주기의 두 시도에 같은 키를 주면 되지 않나 — 그러면 시도 층이 무너진다.
> **한쪽을 고치면 다른 쪽이 깨지는 자리다.**"*

**두 선택지만 놓고 본 게 틀렸다.** 키를 주기 단위로 올릴 필요가 없다. 시도 단위 그대로 두고
**그 시도를 다시 보내면 된다.**

| | 무엇인가 | 시도 층 |
|---|---|---|
| 새 시도 B 를 만든다 | 새 청구. PG 에겐 별개 건 | 행이 는다 |
| 키를 주기 단위로 | 두 시도가 한 키를 공유 | **무너진다** — *"시도 1회당 정확히 한 번"* 이 성립 불가 |
| **시도 A 를 재전송** | **같은 시도의 재전송** | **안 무너진다** |

재전송이 시도 층을 안 건드리는 이유:

```
행이 안 는다            A 는 여전히 payment 행 하나
상한이 안 흔들린다      PENDING 은 애초에 안 세고, UNKNOWN 은 이미 세어졌다
중복 통보가 안 샌다     결과 통보는 그 행의 전이표가 흡수한다(onApproved/onDeclined)
```

**그리고 이게 멱등키가 원래 겨누던 것이다.** W5D3 §7 이 *"키가 지키는 건 같은 시도의
재전송"* 이라고 정확히 적어놓고, 바로 그 도구를 안 쓴 채 *"키가 이 문제를 못 겨눈다"* 로
결론냈다.

## 4. `UNKNOWN` 도 미결이다 — 그리고 이쪽이 훨씬 흔하다

크래시는 드물다. **타임아웃은 흔하다.**

```
PENDING   보냈는지도 확실치 않다 (결과 반영 전에 죽었다)
UNKNOWN   보냈는데 답을 못 들었다
          ↓
둘 다 "돈이 움직였는지 모른다" — 어느 쪽이든 새 청구를 낼 근거가 없다
```

프로젝트는 반대 방향에서 같은 규칙을 이미 세워뒀다 — `RefundRepository:132`
*"PG 무응답 → UNKNOWN. 예약도 장부도 건드리지 않는다. **정보의 부재라 되돌릴 근거가 없다**"*.
**되돌릴 근거가 없으면 새로 낼 근거도 없다.**

### 세는 것과 새로 내는 것은 다른 문제다

W5D2 결정 (c)는 `UNKNOWN` 을 **시도로 센다**(무한 재시도를 막으려고). 오늘 결정은 `UNKNOWN` 에
**새 청구를 안 낸다**이다. 모순이 아니다 — **질문이 다르다**:

```
상한을 셀 때        "청구를 몇 번 걸었나"        → UNKNOWN 은 걸었다. 센다
재전송을 볼 때      "결말을 못 받은 게 있나"     → UNKNOWN 은 결말이 아니다. 재전송한다
```

## 5. 무엇이 재전송을 끝내나 — 안 끝낸다

W5D2 §8 과 같은 모양이 세 번째로 돌아왔다: 재전송은 시도를 안 늘리므로 **상한에 영원히
안 걸린다.** PG 가 계속 답을 안 주면 영원히 묻는다.

**그게 맞다고 봤다.**

```
무한 청구:  매번 돈이 는다.             멈춰야 한다
무한 질의:  같은 키로 같은 걸 묻는다.    답이 오면 자연히 끝난다
```

W5D3 §3 이 *"무한 재전송 루프"* 를 나쁜 것으로 적었는데 그건 **매번 500 을 내는 영구 결함**
이었다. 지금 건 성질이 다르다.

### 대신 조용하면 안 된다

무한히 도는 걸 허용한 대가는 *"영영 안 풀리는 주기가 잊힌다"* 이다. 그래서
`countStaleUnresolvedAttempts` 로 6시간 넘은 미결 시도를 세어 경고한다.

`RefundRepository:58` 이 *"이게 오래 0 이 아니면 UNKNOWN 에 물린 예약이고, 쓸이 배치가 없는
지금 그걸 드러내는 유일한 장치가 대사다"* 로 세워둔 자리와 같다. **지금은 경고 로그뿐이고,
메트릭 승격은 이월이다**(§11).

## 6. ★ 차단기가 미결 시도를 확정하고 있었다

재전송을 넣고 테스트를 돌렸더니 *주기가 `PENDING` 이어야 할 자리*에서 `FAILED` 가 나왔다.
원인은 차단기였다.

```
[실측] 라운드마다 새 주기도 청구하므로 호출이 누적(1+2+…+6=21)
       → pg-approve 개방(minimum-number-of-calls 10)
       → CallNotPermittedException → concludeFailure → 주기 FAILED
```

W4D1 의 근거는 *"차단기가 열려 호출이 PG 에 닿지도 않았다 = 확실한 앎이라 `FAILED` 로
확정해도 이중청구가 안 열린다"* 였다. **그건 새 시도에만 참이다.**

> **재전송이 안 나간 건 원래 요청이 어떻게 됐는지에 대해 아무것도 안 알려준다.**
> 여기서 실패로 확정하면 *"모른다"* 를 잃고, 그 시도는 다시 물어볼 대상에서 빠진다.

그래서 재전송이면 아무것도 안 하고 물러난다. 다음 폴링이 같은 키로 또 묻는다.

**W4D1 의 판단이 틀린 게 아니라 정의역이 좁아진 것이다** — 그때는 시도가 전부 새 시도였다.
W5D3 §6 의 off-by-one 과 같은 모양이다: *"버그를 넣었다"* 가 아니라 **"전제가 만료됐다"**.
이 프로젝트에서 이틀 연속 같은 종류가 나왔다.

## 7. 두 종류의 단언 — 파일 안에서 절을 갈랐다

재전송으로 닫았다고 주장하려면 **PG 가 같은 키에 한 번만 과금한다**가 참이어야 하는데,
그건 **우리가 검증할 수 없는 외부 계약**이다. 그래서 테스트 파일을 둘로 갈랐다.

```
§1 우리가 보증하는 것   서로 다른 키를 몇 개 내보냈나 — 전부 우리 쪽 사실
§2 PG 에 기대는 것      같은 키면 한 번만 과금 — 멱등 스텁으로 "그 계약이 참이라면" 을 보인다
```

§2 의 스텁은 **우리가 심은 가정**이다. 그 단언은 PG 가 아니라 우리 믿음을 확인한다
(W4 회고 §4-2). 어제 계기를 우리 DB 에서 PG 호출 수로 바꾼 교훈을 하루 만에 잃지 않으려고
경계를 파일 구조로 남겼다.

> **주의**: PG 호출 횟수는 재전송으로 **안 줄어든다**(여전히 3회). 줄어드는 건 키의 개수다.
> *"그래서 돈이 한 번만 나갔나"* 는 §2 가, 그것도 가정 위에서만 답한다.

## 8. 백스톱이 발화 조건을 잃었다

W5D2 §8 의 *집기 직전 상한*(`hasRetryLeft`)은 **`UNKNOWN` 이 쌓이는 것**을 전제로 했다.
오늘 재전송이 그 쌓임 자체를 없앴다.

```
W5D2  UNKNOWN 마다 새 시도 → 4개째에 백스톱이 주기를 포기시킨다
W5D4  UNKNOWN 은 재전송   → 시도가 1개에서 안 움직인다 → 백스톱이 셀 값이 안 는다
```

~~**백스톱은 남겨뒀다** — 실패가 *확정*된 시도가 쌓이는 경로에서는 여전히 마지막 벽이다.~~
다만 **지금 그걸 재는 테스트가 없다**: W5D2 대조군 B 가 red 로 잡아내던 시나리오가
사라졌으므로, 백스톱을 지워도 red 를 낼 테스트가 없다.

> **정정 (W5D5)**: 취소선 문장은 **그 경로를 지목하지 않은 채** 썼고, 다음 날 찾아보니 없었다.
> [실측] 세 경로(사다리 소진 · 4번째 타임아웃 뒤 재집기 · 웹훅이 미결을 닫음)에서 **백스톱
> 발화 0회**다. 특히 **결말난 시도가 4개인 주기가 다시 집히는데도** 안 걸린다 — 오늘 넣은
> **재전송 분기가 백스톱 앞에 있기 때문**이다. 4번째 결말이 `FAILED` 면 통보가 주기를
> `ABANDONED` 로 보내고, `UNKNOWN` 이면 그 자신이 미결이라 재전송으로 빠진다.
> **틀린 건 *"남겨뒀다"* 라는 결정이 아니라 그 근거(*"마지막 벽"*)** 이고, 오늘의 재전송이
> 어제의 전제를 없앴는데 같은 날 못 알아본 것이다. 지울지는 W5D5 대조군 D
> (*재전송 분기를 걷어내면 백스톱이 되살아나는가*)가 가른다.
> → [W5D5](W5D5_아무도_안_재던_자리.md) §5

**W5D2 대조군 D(P1 리스)와 같은 자리에 하나가 더 생겼다**(§11 이월 4).
해당 테스트의 javadoc 에 경위를 적어뒀다 — 이름도 뜻에 맞게 바꿨다
(`UNKNOWN_만_쌓여도_네_번째_시도에서_멈춘다` → `UNKNOWN_은_재전송되므로_시도가_쌓이지_않는다`).

### 테스트 둘의 뜻이 바뀌어 손댔다

오늘 변경으로 **어제까지 참이던 단언 둘이 거짓이 됐다.** 둘 다 *"고친 뒤의 사실"* 로 옮겼다.

옮겼고**, 어제 수치는 W5D3 문서 §7 과 클래스 javadoc 에 남겼다.

## 10. Claude 오류

| | 단정 | 어떻게 드러났나 | 실제 |
|---|---|---|---|
| ① | W5D3 §7 *"한쪽을 고치면 다른 쪽이 깨지는 자리다"* | 본인이 *"재전송이다"* 라고 답하면서 | **세 번째 선택지를 못 봤다.** 그리고 그 단정이 어제 문서의 결론 문장(*"키는 이 문제를 못 겨눈다"*)을 한 칸 넓게 만들었다 — 이틀치 문서를 오늘 고쳐야 했다 |
| ② | 재전송을 넣으면서 **차단기 상호작용을 예상 못 했다** | 테스트가 `PENDING` 이어야 할 자리에서 `FAILED` | 차단기가 미결 시도를 확정한다(§6). 설계 때 *"미결이면 아무것도 확정하면 안 된다"* 를 재전송 경로에만 적용하고 **실패 경로에 안 적용했다** |
| ③ | **§2 첫 테스트가 아무것도 안 재고 있었다** | 수치가 *"요청 2회 · 과금 2회"* 로 나왔는데 재전송이 한 번도 안 일어남 | 시나리오가 그 창을 안 만들었다(재시도가 바로 성공해 미결 시도가 안 생김). **green 이었고 단언도 통과했다** — W4D5·W5D1 의 거짓 초록 계열이고, 이번엔 *"통과하는데 겨누는 게 없는"* 종류 |

**①이 제일 나쁘다.** 틀린 사실이 아니라 **선택지를 닫아버린 단정**이라, 그대로 뒀으면
*"이 문제는 원래 안 풀린다"* 가 프로젝트의 결론으로 남았을 것이다. 본인이 *"재전송이다"* 로
연 자리다.

**③은 성질이 흥미롭다.** 계기(멱등 스텁)를 새로 만들었는데 **그 계기가 겨눌 상황을 안
만들었다.** 어제 *"계기를 바꿨다"* 로 하루를 쓰고, 오늘은 바꾼 계기를 **빈 곳에 댔다.**

## 11. 음성대조군

예측을 먼저 적고 본인이 실행했다.

| | 제거 대상 | 겨누는 것 | **예측(먼저 적음)** | 결과 |
|---|---|---|---|---|
| A | `stageAttempt` 의 재전송 분기 | 오늘 변경 전체 | **5건 red** — 재전송 4건 전부 + `DunningSchedulerTest` UNKNOWN 1건 (어제 상태로 완전 복귀) | 미실행 |
| **B** | `charge()` 의 `if (attempt.resend()) return` | 차단기가 미결을 확정 | **1건만** red(`답을_못_들으면…`, 주기가 `FAILED`). ★ 나머지 재전송 3건 green | ★ **적중** |
| **C** | `findUnresolvedAttemptId` 에서 `UNKNOWN` 제외 | `PENDING` 만으로 충분한가 | **3건 red**. ★ **크래시 테스트는 green** — 크래시는 `PENDING` 을 남기니까 = *드문 쪽은 막히고 흔한 쪽은 안 막힌다* | ★ **적중** |
| **D** | `reportStaleUnresolved` 호출 | 관측 | ★ **red 0건** — 로그로만 넣고 재는 테스트를 안 짰다 | ★ **적중 — red 0** |

### C — 오늘 결정의 무게가 여기 있다

`PENDING` 만 재전송해도 **크래시 테스트는 green 이다.** 즉 `UNKNOWN` 을 빼도 *드문 쪽*은
막히고 **흔한 쪽만 뚫린다** — 그리고 그 상태로도 테스트가 3/4 은 통과한다.

`UNKNOWN` 을 미결에 넣은 게 오늘의 실질이고, 그게 없었으면 *"닫았다"* 고 쓰면서 **가장 자주
열리는 문을 열어둔 채**였을 것이다.

### D — red 를 못 내는 게 결론인 대조군, 두 번째

W5D2 대조군 D(P1 리스)에 이어 두 번째다. **관측을 넣고 재지는 않았다**가 그대로 기록된다.
§8 의 백스톱까지 합치면 **지금 red 를 낼 수 없는 자리가 셋**이다:

```
W5D2 대조군 D   P1 리스(구독 시계 CAS)
W5D4 §8         집기 직전 백스톱 — 오늘 발화 조건을 잃었다
W5D4 대조군 D   STALE 관측
```

셋 다 *"있는데 아무도 안 재는 것"* 이고, 셋 다 **없어도 오늘의 스위트는 전부 green** 이다.
W5D5(k6 · 최종 정리)에서 볼 목록이 여기 있다.
