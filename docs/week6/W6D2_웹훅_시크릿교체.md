**날짜**: 2026-10-21 (W6D1 과 같은 날, 두 번째 작업)
**산출물**: 이 문서 + `VerifiedKey` + `WebhookMetrics` + `WebhookSecretRotationTest` 8건 + `WebhookSignatureTest` +1건
+ 시크릿 교체 가이드 정정(`docs/SettleFlow_웹훅_시크릿교체_구현가이드.md`)

> **증거 원칙**: 아래 `[실측]` 은 실제 실행 결과다. 음성대조군 둘은 **사용자 요청으로 Claude 가 실행**했고,

## 1. 오늘의 범위

W6D1 의 검증기는 시크릿이 하나였다. 교체하는 순간 PG 와 우리 중 먼저 바뀐 쪽이 생기고, 그 사이 통보는 전부
401 이다. W6D1 §4 정정 덕에 401 은 재전송되므로 **유실되진 않지만** 전환이 끝날 때까지 결제 반영이 멈춘다.

교체 기간 동안 신·구 키를 둘 다 받고, 구 키 사용이 멈춘 걸 **확인한 뒤** 구 키를 내린다.

```
current  (secret)           검증 + sign()
previous (previous-secret)  검증만. 비어 있으면 "교체 기간 아님"
```

순서: 받을 준비(우리 배포) → PG 전환 → 구 키 사용량 0 확인 → 구 키 제거.
1단계가 PG 전환보다 늦으면 전환 구간 통보가 전부 401, 4단계를 확인 없이 하면 아직 구 키로 보내던 PG 서버의 통보가 401.

## 2. ★ 헤드라인

```
① [실측] 공백 한 글자 " " 는 예외가 아니라 "키"가 된다
   필터가 없으면 공백으로 서명한 요청이 PREVIOUS 로 통과한다 — 가이드는 이걸 500 경로로 예상했다

② 가이드 원안의 "빈 previous" 테스트는 아무것도 못 잡았다
   현재 키로 서명해서 첫 비교에서 돌아온다 — 구 키 분기를 안 밟는다 (대조군 B 에서 green 확인)

③ "previous 가 0 이면 지운다"는 카운터로는 성립 안 한다
   누적값이라 0 으로 안 돌아오고, 미리 등록 안 하면 0 이 아니라 "없음"이다
```

## 3. 구현에서 가이드와 다르게 한 것

### 빈 구 키 테스트 — 틀린 서명으로, `""` 와 `" "` 를 둘 다

`SecretKeySpec` 은 **길이 0** 만 거부한다. 그래서 필터가 없을 때 망가지는 방식이 값마다 다르다:

| previous | 필터 없을 때 |
|---|---|
| `""` | 현재 키로 실패한 요청에서 `IllegalArgumentException: Empty key` → 컨트롤러 500 |
| `" "` | 예외 없음. 공백 한 글자가 유효한 HMAC 키 → **아무나 맞힐 수 있는 키로 통과** |

`""` 쪽이 생각보다 넓다: 운영 yaml 기본값 `${WEBHOOK_SECRET_PREVIOUS:}` 가 바로 `""` 이다. 필터가 없으면 교체 기간이 아닌
**평소 상태**에서 위조·시크릿 불일치 요청이 401 이 아니라 500 이 된다.

테스트는 셋으로 나눴다: 빈 구 키(`""`·`" "`·null) + 틀린 서명 → 예외 없이 실패 / 공백 구 키 + 공백으로 서명 → 실패 /
빈 구 키 + 현재 키 서명 → CURRENT(이게 가이드 원안 모양이고, 회귀 확인용으로만 남겼다).

### 카운터 — 미리 등록, 판단은 `increase()`

- 첫 증가 때 등록하면 구 키로 한 번도 안 온 동안 `key="previous"` 시계열이 **없다.** "0 건"과 "수집 안 됨·이름 틀림"이
  같아 보이고, 없는 걸 0 으로 읽고 구 키를 지우면 그게 바로 막으려던 401 사고다. `SettlementMetrics` 의 `NaN`/`absent()`
  이야기(W4D2)와 같은 자리인데 위험 방향이 반대다 — 거기선 "없음"을 "0초"로 오독, 여기선 "없음"을 "사용 끝"으로 오독.
- 카운터는 누적이라 0 으로 안 돌아온다. 판단식은 `increase(...{key="previous"}[관찰기간]) == 0`. 재시작 리셋은 `increase()` 가 처리.
- **SETNX 앞에서 센다.** 이유는 §7 질문으로 남겼다.
- 401 은 세지 않는다.
- 이름은 `settleflow_` 접두어(`SettlementMetrics` 관례). 가이드의 `webhook_signature_verified_total` 에서 바뀜.

### 생성자 — 테스트 편의 2인자를 남겼다

가이드가 준 두 안 중 "2인자 생성자 남기기"를 골랐다. 기존 `WebhookSignatureTest` 의
`new WebhookSignatureVerifier("not-the-secret", 300)` 두 곳을 안 건드린다. `@Autowired` 는 3인자에만.

## 4. 카운터 배선 — 통합 테스트 1건

`WebhookSignatureTest.서명_통과는_키별로_세고_401은_안_센다`: 401 뒤 `current` 그대로 → 정상 서명 뒤 `current +1`,
`previous` 그대로. 테스트 앱엔 구 키가 없어 `previous` 는 늘 수 없다 — 그래도 `meterRegistry.get(...).tag("key","previous")`
가 예외 없이 값을 돌려준다는 것 자체가 **미리 등록**의 확인이다.

키별 판정(CURRENT/PREVIOUS)은 컨테이너 없는 `WebhookSecretRotationTest` 가 본다. 서명은 검증기의 `sign()` 이 아니라
테스트 안의 독립 HMAC 으로 만든다 — `sign()` 은 현재 키로만 서명해 "구 키로 서명한 요청"을 만들 수 없고, 검증기로
검증기를 재면 둘이 같이 틀릴 때 못 잡는다(W6D1 고정값 대조와 같은 이유).

## 5. ★ 음성대조군 — A 적중, B 빗나감

**실행**: 사용자가 "네가 돌려". `WebhookSignatureVerifier` 가 미커밋 상태라 `git checkout` 원복이 불가능했다 — 이번 작업까지
날아간다. scratchpad 에 백업을 뜨고, 매번 백업본으로 되돌린 뒤 `cmp` 로 동일 확인. **사전 예측은 사용자도 Claude 도 안 적었다**
— 비교 대상은 가이드의 기대뿐이다.

```
[실측 2026-10-21] A. 구 키 대조 블록 제거  → 1 red / 7 green
  🔴 교체기간엔_구키로_서명해도_PREVIOUS로_통과한다   Expecting Optional to contain: PREVIOUS but was empty.

[실측 2026-10-21] B. 빈 값 필터 제거(isBlank 조건 삭제) → 3 red / 5 green
  🔴 교체가_끝나면_구키_서명은_실패한다                IllegalArgumentException: Empty key  (hmac ← verify)
  🔴 빈_구키는_키로_취급하지_않는다_…                  IllegalArgumentException: Empty key
  🔴 공백_구키로는_서명이_통과하지_않는다              Expecting an empty Optional but was containing value: PREVIOUS
  🟢 빈_구키여도_현재키는_그대로_통과한다             ← 가이드 원안 모양. 필터가 없어도 green

[실측] 원복 후 WebhookSecretRotationTest 8/8 · WebhookSignatureTest 8/8 green
```

| 가이드 기대 | 결과 |
|---|---|
| A: "구 키 (교체 기간)"만 red | **적중** |
| B: `" "` + 틀린 서명 → 예외(500 경로) | **빗나감.** 예외는 `""` 에서만, `" "` 는 통과 |

### B 에서 읽을 것 셋

1. **"교체가 끝나면" 이 red 다.** 이 케이스는 빈 값 처리를 겨냥한 게 아니었는데 `previous=""` 라서 걸렸다. 즉 이건
   교체 기간의 사고가 아니라 **교체가 끝난 평소 상태**의 사고다 — §3 의 "평소에 500" 이 실측으로 확인됐다.
2. **가이드 원안 케이스가 green** — §2 ② 가 추측이 아니라 실측이 됐다.
3. **단언 순서가 관측을 가렸다.** `빈_구키는…` 은 첫 단언(`""`)에서 예외가 나 뒤의 `" "`·null 단언이 실행조차 안 됐다(W3D4 와 같은 현상).
   `" "` 를 별도 테스트로 둔 덕에 빈 곳은 없다 — 한 테스트에 묶었으면 `" "` 의 통과는 이 실행에서 안 보였다.
