# SettleFlow 5주 프로젝트 — 일일 성장 체크리스트

세션(대화) 끝날 때 이 5줄을 채워서 Claude에게 붙여넣으면, 그날 대화 내용과 대조해서 실제로 지켰는지 교차검증해줍니다.

> **자기보고만으로는 안 된다.** 이 기록의 실패 방향은 부풀리기가 아니라 **과소보고**다(#1 3세션 연속, W2D5 #3). 그래서 값어치는 5문항 자체가 아니라 **대화 기록과 대조하는 절차**에 있다 — 채우기만 하고 대조를 안 하면 효과가 크게 떨어진다.

---

## 사용법
1. 매일 작업 마무리 시점에 아래 템플릿을 복사해서 채우기
2. 오늘 대화 마지막에 채운 걸 붙여넣고 "오늘 체크리스트 확인해줘"라고 요청
3. 주 단위로 이 파일 맨 아래 "주간 회고" 섹션에 요약 남기기

### 작업 규약 (W2D5 합의)
- **음성대조군은 Claude 가 먼저 돌리지 않는다.** 무엇을 제거할지까지만 말하고 실행·관측·원복은 본인에게 넘긴다. *5세션 연속 미이행의 원인 절반이 "Claude 가 빠르니까 먼저 해버림"이었다 — 기록은 실패를 셌지만 원인은 못 짚었다.*
- **Week 섹션의 Day 요약은 한두 줄 + 링크.** 상세는 `docs/weekN/` 문서가 갖는다. 요약이 문단이 되면 문서와 중복이고 순수 오버헤드다.

> **#5 가 왜 이걸로 바뀌었나(W2D5).** 원래 *"선택지+트레이드오프로 물어봄"* 이었는데 거의 매 세션 "없음/부분적"이라 #4 첫 칸과 같은 것을 두 번 재고 있었다 → #4 로 합쳤다.
> 빈자리에 들어온 건 5세션째 0 이던 **"반박 1회"** 숙제를 **과제형으로 바꾼 것**이다. 반박은 성향이라 할당량으로 요구하면 반박거리가 없을 때 억지가 되고, 5세션 연속 "안 했음"을 적는 건 측정이지 개입이 아니다. 반면 *"검증 없이 단정한 것 찾기"* 는 **할 일**이고 공급도 실재한다(W1D1 repo visibility, W1D5 오류 2건).

4. AI 활용 로그 3줄:
   - AI 제안했지만 내가 거부/수정한 것: **없음**. 오히려 내 제안("방법1 먼저, 2 나중")을 Claude가 순서 뒤집자 해서 수용. Day1의 repo visibility 같은 반박은 오늘 0건

     - 음성 대조군 = "이 테스트가 빨간불 낼 능력이 있는가"를 확인 (가드 빼서 11000 관측)

**갚을 숙제**: 다음 세션에 골격 안 보고 검증 테스트 하나를 **처음부터 혼자** 작성(예: `CHECK (stock >= 0)`가 음수 재고 막는가). 그래야 "받은 이해"가 "가진 기술"이 됨.

### [Week 1 / Day 3] 오늘 한 일

1. 설계 먼저 혼자 해봄: **부분적**

   - **못 했음**: `PaymentAnomaly` 컬럼 구성 질문에서 "뭘 말하는지 모르겠다"고 막힘 → Claude가 시기상조라 판단하고 Week 3으로 연기. ERD 툴 export를 **두 번** 플레이스홀더(`Key`/`Field`) 상태로 제출

2. 코드 받고 내 말로 재설명 시도: **안 함** (요청도 없었고 자발적으로도 안 함)

3. AI 없이 혼자 푼 것: **있음 — Day 2보다 확연히 두꺼움**
   - **데드락 진단 + 해법**: "데드락 나는 거 아니야? 상품 id 순서대로 정렬해서 락 잡으면 될 듯" — 힌트는 "원인은 순서입니다" 한 줄뿐이었는데 진단과 처방을 한 번에 맞힘
   - **`onApproved()` / `onDeclined()` 전이 로직**: §4 전이표만 보고 `IGNORED`/`CONFLICT`/`TRANSITIONED` 분기를 정확히 작성
   - **"TTL 거는 건 굳이 아닌가?"**: Claude가 묻기 전에 스스로 제기
   - "만일 결제하지 않았다면 다른 사람이 선택할 수 있어야 하니까" — `PX`(TTL)의 존재 이유를 스스로 도출
   - DDL 대부분 (제약 이름 규칙, 부분 유니크 인덱스 문법을 찾아서 적용)

4. AI 활용 로그 3줄:
   - **AI 제안했지만 내가 거부/수정한 것**: **0건.** (Day 2와 같음)
     단 **계획서**는 반박함 — Redis 재고 락 폐기. 다만 이건 Claude가 "StagePass 재사용은 면접에서 안 통함"이라고 먼저 몰아간 자리라, **엄밀히는 유도된 반박**이다. Claude의 제안 자체를 되받아친 사례는 오늘 없음
   - **AI 도움으로 처음 알게 된 개념**:
     - `@Enumerated` 없이 enum을 쓰면 `ORDINAL`(숫자)로 저장 → enum 순서를 바꾸면 **저장된 값의 뜻이 통째로 바뀜**(`PAID`였던 결제가 `FAILED`가 됨)
     - `updatable = false`는 **UPDATE에서만** 뺀다 — INSERT엔 포함되므로 `refundedAmount`를 0으로 초기화 안 하면 NOT NULL 위반
     - `@Modifying(clearAutomatically = true)` — 네이티브 UPDATE는 1차 캐시를 모른다. 안 비우면 차감 전의 낡은 값을 계속 들고 있음
     - `DataIntegrityViolationException`은 CHECK/FK/UNIQUE/NOT NULL을 싸잡는 **우산 예외** → 제약 이름까지 못 박아야 가짜 통과가 안 남
     - `TIMESTAMP`엔 타임존이 없다 → "며칠자 매출" 경계가 흔들리고 PG 리포트 대사가 어긋남
     - 인자 있는 생성자를 만들면 **기본 생성자가 사라진다** (JPA는 리플렉션으로 빈 객체를 만들므로 `protected Xxx() {}` 필수)
     - `updated_at`은 "이 행은 변한다"는 **선언** — 불변 테이블(`order_item`/`refund`)에 붙이면 잘못된 신호를 준다
   - **완전히 혼자 해결한 문제**: 데드락 진단·정렬 해법, `onApproved`/`onDeclined` 전이 로직, TTL 불필요 판단

## Week 3 — 정산 배치 + 대사(Reconciliation)

- Day 1: 이벤트 스키마 + 트랜잭셔널 아웃박스 → [week3/W3D1_이벤트_아웃박스.md](week3/W3D1_이벤트_아웃박스.md). dual-write 를 **트랜잭셔널 아웃박스**로 없앰(journal INSERT 와 같은 tx) — W1D3 "재고 진실이 갈라진다"·W2D4 "저장하면 진실이 둘"의 세 번째 적용. 릴레이는 **Quartz 폴링**(CDC 는 인프라 없음), 스키마는 JSON·**fat 스냅샷**·타입별 토픽. `outbox.published_at` UPDATE 가 append-only 위반이 아닌 근거를 세움(**진실 vs 전송 큐**) — W3D2 에서 재사용됨. 실측 3케이스 + **Quartz 자동 발행을 bootRun 으로 실측**해 미검증 항목 닫음. 전체 **53 → 56건 0실패**.
- Day 2: 환불 Saga — Consumer + 보상 → [week3/W3D2_환불사가_보상.md](week3/W3D2_환불사가_보상.md). 계획서의 "보상 트랜잭션"을 **구현하지 않고 필요 없게 만듦** — 역분개를 PG 확인 뒤로 미루니 취소할 장부 기록이 애초에 없다(*안 적었으니 지울 것도 없다*). 미루기는 **본인 발의**. 다만 `refunded_amount` 누적은 안 미룸 — 그게 판정 그 자체라 미루면 판정할 근거가 없어진다(W1D2 레이스 부활). **예약 vs 기록**으로 갈랐고, 이건 W1D3 재고 예약 패턴의 이식. `UNKNOWN` 에 예약을 안 푸는 이유는 **W1D5 이중판매 구멍의 환불판**(복원은 시간이 아니라 사실 확인의 문제). 멱등은 `event_id UNIQUE` 제안이 **성립 안 함을 지적받아**(소비자는 INSERT 를 안 한다) 조건부 UPDATE 의 affected rows 로 정정 — 상태와 멱등이 한 컬럼을 공유. fat 스냅샷을 `requested`→`completed` 로 재배치(거울 규칙을 지킬 수 있는 유일한 지점). 실측 8케이스 + **테스트 yaml 이 메인 yaml 을 통째로 가리던 설정 버그**를 리스너 실패로 발각·제거(별도 커밋). 전체 **56 → 64건 0실패**. **★ red-light 를 6세션 만에 본인이 직접 이행** — 멱등 두 겹을 다 제거, **예측을 먼저 적고**(2건 red / journal 3) 대조해 적중. 다만 예측이 못 맞힌 게 둘: 피해의 형태가 개수가 아니라 **장부 15,000 vs 예약 5,000 드리프트**였다는 것, 거절 경로는 틀린 숫자가 아니라 **언더플로 백스톱이 예외로 정지**시킨다는 것.
- Day 3: 야간 정산 배치 → [week3/W3D3_정산배치.md](week3/W3D3_정산배치.md). **W1D3·W2D4에서 두 번 기각한 "저장"을 오늘은 채택** — 구분선은 *복제냐 별개의 사실이냐*(정산액은 "그날 그렇게 판단했다"는 사실이라 어긋남이 버그가 아니라 정보). 집계 원천을 **장부**로 골라 환불의 날짜 귀속이 공짜로 따라왔고(`refundStatus()` 를 한 번도 안 씀 → W3D2 이월을 오늘 안 만남), net(`SELLER_PAYABLE` 의 `CREDIT − DEBIT`)만 저장. **경계를 시간으로 자르기로 하면서 "커밋 가시성 구멍"을 알고 뚫었다**(타임스탬프 순서 ≠ 가시성 순서 → 늦게 커밋된 줄이 어느 정산에도 안 들어가고 증발) — 상환은 W3D5. **덮어쓰기를 고른 덕에 재실행이 그 구멍의 복구 수단**이 됐다. V8에 CHECK 이 하나도 없는 게 판단인 이유(`settlement == SUM(ledger)` 는 어긋날 수 있는 관계 → 제약이 아니라 **대사**의 영역)가 W3D4의 존재 이유로 이어짐. 집계+upsert 를 `INSERT ... SELECT ... ON CONFLICT` **한 문장**으로. 실측 6케이스, 전체 **64 → 70건 0실패**. **음성대조군(본인 실행·원복)**: 부호 제거 → **2 red / 4 green** — 4개가 통과한 게 본체(그 데이터엔 `DEBIT` 줄이 없어 분기를 안 탄다, W2D5 뺄셈 제거와 같은 모양). 오차가 환불액의 **2배**이고 **항상 셀러에게 유리한 방향**이라 아무도 신고하지 않는다 = 대사 말고 발견 경로가 없다. 절차상 발견: 원복은 정상이었으나 **Claude 가 준 원복 *증명* 절차(`git diff --stat`)가 틀렸다** — `settlement/` 가 untracked 라 기준선이 없어 원복 여부와 무관하게 diff 가 비어 있다. W2D4에서 통한 방식을 확인 없이 이식한 것. ⚠️ **예측 선기록 미이행** — W3D2에 붙은 습관이 한 세션 만에 빠짐.
- Day 4: 대사(Reconciliation) → [week3/W3D4_대사.md](week3/W3D4_대사.md). 셋을 했다. **①W3D2 이월 청산** — `refunded_amount` 가 예약(COMPLETED+REQUESTED+UNKNOWN)이 됐는데 라벨이 거기서 파생돼 진행중인 환불을 환불로 셌다. 한 컬럼이 *가드(예약 포함해야 정확)*와 *라벨(빠져야 정확)*을 겸할 수 없어 **라벨이 원천을 옮겼다**(→ `pg_status='COMPLETED'` 합, 파생 유지). 컬럼·메서드 개명(V9 `reserved_refund_amount`/`reserveRefund`). 201 응답은 **두 축을 다 노출** — 전액 요청 직후 `NOT_REFUNDED` + `remainingRefundable=0` 이 모순처럼 보이지만 **그 조합이 다음 요청의 409 를 미리 설명한다**. **②내부 축 대사** — 배치와 같은 SQL 을 재실행하면 **동어반복**(가계부를 두 번 읽는 것)이라 원천을 `payment`+`refund` 로 바꿈. W3D3 §2 가 안 고른 길이 대사에선 장점. 대가로 날짜 경계(`payment` 에 승인 시각 컬럼이 없어 journal 에서 시각만 빌림)와 환불 안분(의도적 복사)은 독립이 아니다 → **W2D5 승격 트리거는 이 대사로 안 울린다**고 확정. **③외부 축 대사** — Mock PG CSV(승인·환불 한 파일 `type`). **상태 칸을 안 둔다: 정산 리포트엔 실패한 거래가 없어 존재 자체가 상태다**(⑤의 "상태 다름"이 "있음/없음"으로 흡수, `UNKNOWN` 은 리포트에 없어도 거절이 아니라 미확정 — W1D1 §3). **조인 키를 `pg_transaction_id`→`merchant_payment_id` 로 교체**(전자는 웹훅 경로에만 채워져 동기 승인엔 없다 — 계획서·W3D1 상정이 성립 안 함). **주말 체크포인트 달성: 3건 심고 정확히 3건**(웹훅유실/금액다름/리포트에없음). 전체 **70 → 83건 0실패**. **음성대조군(본인 실행·원복)**: W3D3 §8 이 기대로만 남긴 *"대사 말고 발견 경로가 없다"* 를 **실측으로 닫음 — 대사가 2건 잡았다**(오차 합 10,000 = 환불액의 2배, 부호 둘 다 과지급 방향). ⚠️ **그런데 그 증거가 단언에 없었다** — 빨간불은 *정산* 단언에서 났고 AssertJ 가 첫 실패에서 멈춰 대사 단언은 실행조차 안 됐다. 대사가 잡았다는 사실은 **`[실측]` printf 에만** 남았다(W1 부터의 관습이 처음으로 단언이 못 본 걸 봤다) → 테스트 결함으로 보고 **"클래스가 겨누는 축의 단언이 먼저"** 를 규약화.
- Day 5: 스냅샷 기준 조회 + 불일치 자동 플래그 → [week3/W3D5_스냅샷_불일치플래그.md](week3/W3D5_스냅샷_불일치플래그.md). **②W3D3 §4의 증발 구멍 상환** — 배치의 `WHERE` 한 줄이 *"언제 귀속되는가"*(persist 때 멈추는 시계)와 *"이미 셌는가"*(커밋 때 움직이는 시계)에 **동시에 답하고 있었다**는 게 원인. 축을 나누니(`V10 settlement_pending`, 트리거가 INSERT) W3D3 §4 표의 이분법 자체가 무너졌다 — **(나)가 뜻을 흐린 건 상태로 잘라서가 아니라 주운 줄을 주운 날에 넣었기 때문**이라 (다)에선 증발 없음과 날짜의 뜻이 **둘 다** 성립한다. 표식은 집계 대상을 정의하지 않게 두어(전체 재집계+덮어쓰기 유지) **정확성의 임계 경로 밖**에 놨고, 그 덕에 `V10` backfill 이 안전하다. `REPEATABLE READ` 로 집계와 표식삭제를 **같은 스냅샷**에 묶음(`READ COMMITTED` 는 문장마다 새로 떠서 밀리초짜리 구멍이 남는다). 두 오류 방향이 **비대칭**(안 셌는데 지우면 증발/셌는데 안 지우면 무해)이라 RR 직렬화 실패로 롤백돼도 **피해가 증발이 아니라 지연**. 진입점 `settleYesterday()` → `runPending()`(계산이 아니라 **물어본다**), 별도 빈인 이유는 **프록시 경계**(같은 클래스면 격리 수준이 조용히 무시된다). **①불일치 자동 플래그** — 저장 여부보다 **수명**이 먼저였다: ② 이후 `MISSING_IN_SETTLEMENT` 가 일시적이 되어 값어치가 *"지금 어긋남"*이 아니라 **"며칠째 안 메워짐"**으로 옮겨갔고, 그건 관측을 쌓아야 나온다(`V11`, 상태 UPDATE 대신 append-only — W2D1 §5). 대가로 *"안 나타남"*이 **깨끗했다/안 봤다** 둘을 뜻하게 돼 **실행 기록 테이블**이 함께 필요(W3D4 `ONLY_IN_INTERNAL` 의 모호함과 같은 계열 — 거기선 못 풀었고 여기선 기록으로 풀었다). **★날짜 출처가 셋**(정산이 돈 날짜 / 미해소 날짜 / 최근 7일)이고 셋째가 핵심 — ①만 두면 대사가 **감시 대상에게서 볼 목록을 물려받아**, 트리거가 죽으면 정산 대상 0건 → 대사도 눈 감음 → **모든 장부가 증발하는 동안 초록불**. W3D4 가 *금액 계산*은 독립으로 만들었는데 ***무엇을 볼지***는 안 그랬던 자리. 발견 둘: **`ReconciliationService` 를 프로덕션에서 아무도 안 부르고 있었다**(W3D4 는 비교 로직만 만들고 멈춤), 오늘 ②가 기존 대사 테스트를 안 깨뜨린 건 그 테스트가 `settle()` 을 손으로 부르기 때문. 실측 3+4케이스, 전체 **83 → 90건 0실패**. 커밋 `c3768a5`·`c3f523d` — **각각 독립 컴파일됨을 워크트리로 확인**. **음성대조군 A~D 본인 실행·원복 완료**(§11) — A 🔴1건(`survivors=0`) / B 🟢 / C 🟢 / D 🔴1건(`대사대상=0건`). **값은 어긋난 칸 둘에서 나왔다**: ① A 에서 예측이 갈렸고 red 가 나 *케이스 ③이 RR 을 실제로 지킨다*가 확정, ② **A red + B green 이 짝을 이뤄** *테스트가 건 RR 은 검증되고 프로덕션 애노테이션은 안 된다*를 추측에서 실측으로 바꿈. ③ **★D 1차 시도가 무효였다** — B·C·D 를 전부 `SettlementConcurrencyTest` 필터로 돌렸는데 D 가 건드리는 `ReconciliationRunner` 를 그 클래스는 주입조차 안 받아 **red 를 낼 능력 자체가 없었다.** 둘 다 red 를 예측했다 green 을 보고 "출처 ③ 없어도 되네"로 읽으면 정반대 결론이다 → **규약 추가: 제거 대상을 정할 때 그것을 겨누는 테스트 클래스를 같이 적고 실행 필터에 들어갔는지 확인**(대상을 주며 안 적은 건 Claude 누락). 올바른 필터로 재실행하니 예측대로 1건 red 이고 printf 가 논증을 문자 그대로 보여줬다(`대사대상=0건` = 대사가 눈을 감는다). **`EXPLAIN` 3회 이월 숙제도 닫음**(§13) — 12,000행에서 날짜 단독 조회가 `uq_settlement_date_seller` 를 **`Sort` 없이** 타고(컬럼 순서의 값어치), 셀러 인덱스를 지우면 `Seq Scan` 으로 11,700행을 버린다(UNIQUE 가 대신 못 함). **여기서도 1차 측정이 무효였다** — 리터럴 `seller_id=7` 이 실존 id 가 아니라 `rows=0`, 플랜 *모양*은 유효했지만 경로를 안 밟았다. **같은 함정이 코드·음성대조군 절차·측정 하네스 세 층위에서 나온 날.** STAR #3(정산 대사) README 작성 완료(3/4). 전체 **92건 0실패**.

**교차검증(Claude)**: **#1·#2 정확.** 오늘 설계 판단은 거의 전부 본인 발화였고(목표 선택 · 두 질문 분리 · 표식 역할 · RR · 비대칭 · 별도 테이블 · pending 큐 · 진입점 · 트리거 · 관측 누적+실행 기록 · 날짜 출처 확장) 코드는 확정 후에만 나갔다. #2 는 요청 2회(프록시 경계 / `살아남은 표식=1`)에 둘 다 무응답 — 정직한 자기보고이고 **W3D3부터 3세션 연속 공백**이다.

**#3 은 과소보고 + 무게 미구분.** 적힌 셋의 무게가 다르다 — **두 질문 분리는 오늘의 본체**다(*"장부 줄은 언제 귀속되냐, 배치는 이미 셌냐"*, 힌트는 "둘로 나눠 적어보라"뿐이었고 **그게 W3D3 표의 이분법을 깼다**). 반면 *표식 역할*은 제시된 선택지 둘 중 고른 것이고, *RR* 은 Claude 가 *"`READ COMMITTED` 는 문장마다 스냅샷을 뜬다 — 이 사실이 답을 거의 다 정합니다"* 를 먼저 깔아 이름을 댄 몫이 본인 것이다. **그리고 더 독립적이었던 둘이 빠졌다** — **비대칭 판단**(*"셌다고 잘못 찍는 게 치명적"*, 선택지 없이 물었고 바로 나왔으며 그 답이 "삭제가 정산과 같은 tx" + "RR 롤백이 안전한 방향" 둘을 동시에 정했다)과 **진입점**(*"안 센 날짜 다 도는 걸로"*). **설계 기여를 본인이 지우는 패턴**이 W2D1 §5·W2D2 #1에 이어 또 나왔다.

**#4 첫 칸은 사실과 다르다 — 이 기록에서 드문 *과대*보고.** *"트레이드오프 요구 여러번"* 이라 적혔는데 **오늘 대화에 요구한 자리가 없다.** Claude 가 매 턴 먼저 선택지+대가를 붙였고 본인 메시지는 대부분 결정 통보였다(`②부터`, `ㄷ으로 가고`, `B로 하고`). **받은 것과 요구한 것은 다르다.** 같은 칸의 *"AI 제안 거부/수정"* 도 0건 — **5세션 넘게 이어지는 공백**이다. *"프록시 경계 처음 앎"* 은 맞고, *"완전히 혼자 해결한 문제: 없음"* 은 #3과 모순이다(두 질문 분리가 여기 들어가야 한다).

**#5 「못 찾음」은 틀렸다 — 둘 있었고, 오늘 제일 중요한 칸이다.** ① **음성대조군 D 대상을 주면서 그것을 겨누는 테스트 클래스를 안 적었다** — "1건 red" 를 예측하면서 실행 필터가 `DiscrepancyFlagTest` 를 포함하는지 확인하지 않아 **실험이 통째로 무효**가 됐고, 하마터면 *"출처 ③은 필요 없다"* 는 정반대 결론이 나올 뻔했다. ② **`EXPLAIN` 하네스에 `seller_id = 7` 을 박고 실존 여부를 확인 안 했다** → `rows=0`, 1차 측정 무효. **둘 다 Claude 가 먼저 실토했다고 #5에서 빠지면 안 된다** — 그러면 #5가 *"자백하면 면제"* 가 되어 측정 장치가 망가진다. **#5는 "누가 발견했나"가 아니라 "검증 없이 단정한 게 있었나"를 묻는다.**

[실측] 같은 시나리오의 **키 3개 → 2개**(PG 호출은 그대로 3회 — 줄어드는 건 *PG 가 별개 청구로 볼 것*의 개수다). [실측·가정] 멱등 PG 위에서 **요청 3회 · 과금 2회**. ★ **차단기가 미결 시도를 `FAILED` 로 확정하고 있었다** — W4D1 의 *"안 보냈으니 확실한 앎"* 은 **새 시도에만** 참이다(이틀 연속 *"전제가 만료됐다"*). 어제 만든 백스톱은 **발화 조건을 잃었다.** [실측] 전체 **161건 green**. 음성대조군 **B·C·D 예측 3/3 적중**(D 는 red 0건 = 관측을 넣고 재지는 않았다). ★ **red 를 낼 수 없는 자리가 셋**(P1 리스 · 백스톱 · STALE 관측) — W5D5 목록. - Day 5: 계획서 D5(k6 실행 + 최종 문서)를 **반으로 갈라** k6 는 설계까지만 하고, W5D4 가 남긴 **"red 를 낼 수 없는 자리 셋"** 을 갚았다. W5D4 가 *"마지막 벽이라 남겨뒀다"* 고 쓴 근거가 실행으로 부정됐다 — *"전제가 만료됐다"* **사흘 연속**. 계기는 프로덕션 코드를 안 바꾸고 얻었다(백스톱에서만 찍히는 로그). STALE 은 **쿼리가 아니라 호출의 결과**를 재야 대조군이 red 가 된다. ★ **k6 는 이 시나리오에서 부하 발생기가 아니다** — Dunning 은 폴링으로 스스로 깨어나므로 부하원은 인스턴스 다중화이고 k6 는 계기 쪽으로 물러난다. 어제 *"창이 좁다"* 고 한 것도 **P1 에는 틀려서 정정**했다. 전체 **166건 green**, **프로덕션 코드 무변경(`feat:` 없는 첫 날)**. ★ 음성대조군 **A·B·C·D 예측 4/4 적중**(본인이 넷 다, 각각 전체 스위트로). **A** P1 리스 제거 → 1건 red, ★ **키 개수 단언에서 졌다**(DB 제약 예외가 아니라 — 그래야 리스를 잰 것이다). **C** STALE 호출 제거 → 1건 red(`expected 1 but was 0`), W5D4 에서 red 0 이던 자리다. **B·D 는 짝으로 읽는다** — B: 백스톱을 지워도 **166건 전부 green**(아무도 그 줄을 안 지킨다) / D: 재전송 분기를 걷어내자 **red 6건 + 백스톱이 그 자리에서 1회 발화**. 그래서 백스톱은 죽은 코드가 아니라 **그 분기에 딸린 안전장치**라 **남긴다**(지키는 대상이 시나리오가 아니라 *전제의 회귀*라 테스트가 아니라 주석으로 못 박았다). B 1회차에 **거짓 red 1건**(`CircuitBreakerSmokeTest` 소켓 바인딩 — 우리 코드 밖, 재현 안 됨). ★ **A 를 다시 걸어 크기까지 쟀다: 키 10 · PG 호출 19 · 주기 10**(예측 2~4 는 **빗나갔다** — Claude 오류 ④). `uq_billing_cycle_subscription_no` 가 **한 건도 못 걸렀다**: **행 락이 이미 직렬화**해서 각자 자기 차례에 `max+1` 을 새로 계산하기 때문이다. 즉 **직렬화는 공짜로 얻고 있었고 CAS 는 그 줄에서 승자를 가릴 뿐**이며, 리스가 없으면 무질서가 아니라 **질서 있는 열 번**이 나간다. 이게 *"예외가 아니라 키 개수로 단언한다"* 는 설계를 사후에 정당화했다 — 예외로 단언했으면 **red 가 아예 안 났다.** 호출 19 − 키 10 = **재전송 9**(k6 설계 문서의 항등식이 실데이터에서 성립). Claude 오류 4건(선택지의 **공통 전제**를 안 적은 것이 제일 나쁘다 — W5D4 ①과 같은 계열의 반복). **구독 생성 경로는 네 번째 이월이고, 이제 k6 실행의 선결 조건이 됐다.** → [W5D5](week5/W5D5_아무도_안_재던_자리.md)
