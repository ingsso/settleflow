### [Week 1 / Day 3] 오늘 한 일

1. 설계 먼저 혼자 해봄: **부분적**
   - **했음**: DDL 5테이블을 직접 타이핑(Claude는 `product` 예시 1개만 제시). `GENERATED ALWAYS AS IDENTITY`는 Claude가 쓴 `BIGSERIAL`보다 나은 선택이었음. `total_amount` 저장/`quantity > 0` 판단, `seller` 테이블 필요성도 스스로 추가
   - **못 했음**: `PaymentAnomaly` 컬럼 구성 질문에서 "뭘 말하는지 모르겠다"고 막힘 → Claude가 시기상조라 판단하고 Week 3으로 연기. ERD 툴 export를 **두 번** 플레이스홀더(`Key`/`Field`) 상태로 제출

2. 코드 받고 내 말로 재설명 시도: **안 함** (요청도 없었고 자발적으로도 안 함)

3. AI 없이 혼자 푼 것: **있음 — Day 2보다 확연히 두꺼움**
   - **데드락 진단 + 해법**: "데드락 나는 거 아니야? 상품 id 순서대로 정렬해서 락 잡으면 될 듯" — 힌트는 "원인은 순서입니다" 한 줄뿐이었는데 진단과 처방을 한 번에 맞힘
   - **`onApproved()` / `onDeclined()` 전이 로직**: §4 전이표만 보고 `IGNORED`/`CONFLICT`/`TRANSITIONED` 분기를 정확히 작성
   - **"TTL 거는 건 굳이 아닌가?"**: Claude가 묻기 전에 스스로 제기
   - "만일 결제하지 않았다면 다른 사람이 선택할 수 있어야 하니까" — `PX`(TTL)의 존재 이유를 스스로 도출
   - DDL 대부분 (제약 이름 규칙, 부분 유니크 인덱스 문법을 찾아서 적용)

4. AI 활용 로그 3줄:
   - **AI 제안했지만 내가 거부/수정한 것**: **0건.** (Day 2와 같음)
     단 **계획서**는 반박함 — Redis 재고 락 폐기. 다만 이건 Claude가 "StagePass 재사용은 면접에서 안 통함"이라고 먼저 몰아간 자리라, **엄밀히는 유도된 반박**이다. Claude의 제안 자체를 되받아친 사례는 오늘 없음
   - **AI 도움으로 처음 알게 된 개념**:
     - `@Enumerated` 없이 enum을 쓰면 `ORDINAL`(숫자)로 저장 → enum 순서를 바꾸면 **저장된 값의 뜻이 통째로 바뀜**(`PAID`였던 결제가 `FAILED`가 됨)
     - `updatable = false`는 **UPDATE에서만** 뺀다 — INSERT엔 포함되므로 `refundedAmount`를 0으로 초기화 안 하면 NOT NULL 위반
     - `@Modifying(clearAutomatically = true)` — 네이티브 UPDATE는 1차 캐시를 모른다. 안 비우면 차감 전의 낡은 값을 계속 들고 있음
     - `DataIntegrityViolationException`은 CHECK/FK/UNIQUE/NOT NULL을 싸잡는 **우산 예외** → 제약 이름까지 못 박아야 가짜 통과가 안 남
     - `TIMESTAMP`엔 타임존이 없다 → "며칠자 매출" 경계가 흔들리고 PG 리포트 대사가 어긋남
     - 인자 있는 생성자를 만들면 **기본 생성자가 사라진다** (JPA는 리플렉션으로 빈 객체를 만들므로 `protected Xxx() {}` 필수)
     - `updated_at`은 "이 행은 변한다"는 **선언** — 불변 테이블(`order_item`/`refund`)에 붙이면 잘못된 신호를 준다
   - **완전히 혼자 해결한 문제**: 데드락 진단·정렬 해법, `onApproved`/`onDeclined` 전이 로직, TTL 불필요 판단

5. 선택지+트레이드오프로 물어봄: **부분적**
   - "TTL 거는 건 굳이 아닌가?" — 트레이드오프 성격의 자발적 질문 (**긍정 신호**)
   - "인터페이스 사용?" / "버그 저렇게 수정하라는 거 맞아?" — 확인 질문이지 선택지 요구는 아님
   - 나머지 선택지(A/B안)는 여전히 Claude가 제시하고 고름
