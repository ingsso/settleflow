### [Week 1 / Day 1] 오늘 한 일

1. 설계 먼저 혼자 해봄: **했음**
   - 6줄 초안(스냅샷 복사, 1:N, enum 분리, Long, stock 컬럼, pgTransactionId unique) 작성 후 검토 요청

2. 코드 받고 내 말로 재설명 시도: **해당 없음** (오늘 코드 없음)

3. AI 없이 혼자 푼 것: **있음** — 전이표 `UNKNOWN` 행 3칸(승인→PAID / 거절→FAILED / 타임아웃→UNKNOWN)을 힌트 없이 맞힘. 초안의 스냅샷 복사·pgTransactionId unique는 수정 없이 채택됨

4. AI 활용 로그 3줄:
   - AI 제안했지만 내가 거부/수정한 것: **1건** — Claude가 "저장소가 public이라 docs 노출 주의"라고 단정. 확인해보니 **PRIVATE**이었음. `gh repo view`로 검증 가능했는데 안 하고 추측을 사실처럼 말한 것을 잡아냄
   - AI 도움으로 처음 알게 된 개념:
     - CHECK 제약은 자기 행 하나만 본다 → 테이블 간 집계 불변식을 표현할 수 없음
     - 타임아웃은 실패가 아니라 **정보의 부재**. FAILED로 찍으면 이중청구
     - 웹훅이 동기 응답보다 먼저 도착할 수 있음
     - "무시"는 상태를 무시하는 것이지 사건을 무시하는 게 아님 (웹훅엔 200 OK를 줘야 재전송이 멈춤)
     - GitHub은 기본 브랜치를 삭제 못 하게 막음. `refusing to delete the current branch`의 "current"는 로컬 체크아웃이 아니라 **GitHub 기본 브랜치**를 뜻함
   - 완전히 혼자 해결한 문제: 이상 테이블에 자체 상태가 필요하다는 것을 스스로 제기

5. 선택지+트레이드오프로 물어봄: **부분적**
   - "DB 제약을 걸면 된다는 거 아니야?" — 답을 확인하려는 질문이었지 선택지를 요구한 게 아니었음
   - 선택지(A/B/C안)는 AI가 먼저 제시했고, 그중 고르기만 함

**교차검증(Claude)**: 1·3번은 실제로 채워짐. 4번은 세션 대부분 비어 있었음 — 설계 논의 내내 AI 제안에 대한 반박 0건, 이상 테이블 B안도 권유받자마자 수용. 다만 **세션 막바지에 1건 발생**(저장소 visibility 오류 지적). 설계 영역에서는 여전히 반박이 없었다는 점은 유지해서 볼 것.

**반복된 오류 패턴**: 전이표를 두 번 틀렸는데 두 번 다 같은 원인 — **종착지 상태를 사건이 움직이게 함**(1차: 다른 종착지로, 2차: 왔던 길로). 근본 원인은 "모든 사건이 상태를 바꿔야 한다"는 전제. 실제로는 12칸 중 7칸이 무전이.

**AI 신뢰도 메모**: Claude가 확인 가능한 사실을 검증 없이 단정한 사례가 최소 1건(repo visibility). 같은 세션에서 Postgres 동작 3건도 미검증 상태로 설계 근거에 사용됨 → Day 2에 직접 검증할 것. **말한 것과 돌려본 것을 구분해서 받아들일 것.**

### [Week 1 / Day 2] 오늘 한 일

1. 설계 먼저 혼자 해봄: **부분적** — 테스트 접근("스레드 2개로 동시에 UPDATE 날린다")은 Claude가 배리어를 꺼내기 전에 스스로 제안. 단 스레드 정렬(CyclicBarrier)·트랜잭션 격리·음성 대조군은 몰라서 유도받음

2. 코드 받고 내 말로 재설명 시도: **했음(요청받아서)** — 처음엔 "재구성 못 할 것 같다"고 정직하게 밝힘
   - 재설명 못 한 부분: 음성 대조군(개념 B)을 처음엔 재구성 실패 → 화재감지기 비유로 다시 듣고 핵심("초록불이 가드 덕인지 구분 못 하니까")을 본인 말로 잡음. 단 정확한 프레이밍("테스트가 빨간불 낼 능력이 있는가")은 Claude가 넓혀줌

3. AI 없이 혼자 푼 것: **얇음** — 테스트 접근 제안(스레드 2개), 8000·count=2 판단, `SQLException` 타입(FILL②) 힌트 없이 맞힘, 개념 B 핵심 재구성. **큰 것(배리어·격리·음성대조군·SQL)은 전부 유도받음**

4. AI 활용 로그 3줄:
   - AI 제안했지만 내가 거부/수정한 것: **없음**. 오히려 내 제안("방법1 먼저, 2 나중")을 Claude가 순서 뒤집자 해서 수용. Day1의 repo visibility 같은 반박은 오늘 0건
   - AI 도움으로 처음 알게 된 개념:
     - Testcontainers(테스트가 소유하는 일회용 DB) vs docker-compose(내가 관리하는 장기 인프라)
     - `PreparedStatement`의 `?`/`setLong`은 **2단계** — SQL 문자열엔 빈칸만, setLong은 밖에서 채움 (처음엔 문자열 안에 setLong 넣는 오해)
     - CyclicBarrier = 두 스레드를 억지로 동시에 부딪히게 하는 장치
     - 음성 대조군 = "이 테스트가 빨간불 낼 능력이 있는가"를 확인 (가드 빼서 11000 관측)
     - `assertThatThrownBy` = 값이 아니라 "예외가 나는 것"을 검증
   - 완전히 혼자 해결한 문제: `SQLException` 타입 판단, 8000/count=2 산정

5. 선택지+트레이드오프로 물어봄: **부분적** — "시간 충분한가? 방법1 먼저 하고 2 나중은?"이 트레이드오프 성격의 질문. 나머지 선택지(A/B)는 Claude가 제시하고 고름

**교차검증(Claude)**: 3번은 실제로 얇음이 맞다. Day1(전이표 3칸 독립 해결)보다 독립도가 확연히 낮은 날 — **새 기술(테스트 작성) 첫날이라 위임이 큰 건 자연스럽지만, 체크리스트가 경고한 신호("혼자 푼 것이 비면 위임 과다")에 근접**. 4번 "반박"은 0건(Day1 막바지 1건과 대비). 다만 **긍정 신호**: "모르겠다"를 두 번 정직하게 밝힘(재구성 실패, 개념 B 흐림) — 자기보고 부풀리지 않은 학습 태도.

**갚을 숙제**: 다음 세션에 골격 안 보고 검증 테스트 하나를 **처음부터 혼자** 작성(예: `CHECK (stock >= 0)`가 음수 재고 막는가). 그래야 "받은 이해"가 "가진 기술"이 됨.
