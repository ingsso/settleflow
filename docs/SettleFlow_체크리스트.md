# SettleFlow 5주 프로젝트 — 일일 성장 체크리스트

세션(대화) 끝날 때 이 5줄을 채워서 Claude에게 붙여넣으면, 그날 대화 내용과 대조해서 실제로 지켰는지 교차검증해줍니다.

---

## 사용법
1. 매일 작업 마무리 시점에 아래 템플릿을 복사해서 채우기
2. 오늘 대화 마지막에 채운 걸 붙여넣고 "오늘 체크리스트 확인해줘"라고 요청
3. 주 단위로 이 파일 맨 아래 "주간 회고" 섹션에 요약 남기기

### [Week 1 / Day 1] 오늘 한 일

1. 설계 먼저 혼자 해봄: **했음**
   - 6줄 초안(스냅샷 복사, 1:N, enum 분리, Long, stock 컬럼, pgTransactionId unique) 작성 후 검토 요청

2. 코드 받고 내 말로 재설명 시도: **해당 없음** (오늘 코드 없음)

3. AI 없이 혼자 푼 것: **있음** — 전이표 `UNKNOWN` 행 3칸(승인→PAID / 거절→FAILED / 타임아웃→UNKNOWN)을 힌트 없이 맞힘. 초안의 스냅샷 복사·pgTransactionId unique는 수정 없이 채택됨

4. AI 활용 로그 3줄:
   - AI 제안했지만 내가 거부/수정한 것: **없음** ← 위임 과다 신호. 다음날 개선 필요
   - AI 도움으로 처음 알게 된 개념:
     - CHECK 제약은 자기 행 하나만 본다 → 테이블 간 집계 불변식을 표현할 수 없음
     - 타임아웃은 실패가 아니라 **정보의 부재**. FAILED로 찍으면 이중청구
     - 웹훅이 동기 응답보다 먼저 도착할 수 있음
     - "무시"는 상태를 무시하는 것이지 사건을 무시하는 게 아님 (웹훅엔 200 OK를 줘야 재전송이 멈춤)
   - 완전히 혼자 해결한 문제: 이상 테이블에 자체 상태가 필요하다는 것을 스스로 제기

5. 선택지+트레이드오프로 물어봄: **부분적**
   - "DB 제약을 걸면 된다는 거 아니야?" — 답을 확인하려는 질문이었지 선택지를 요구한 게 아니었음
   - 선택지(A/B/C안)는 AI가 먼저 제시했고, 그중 고르기만 함

**교차검증(Claude)**: 1·3번은 실제로 채워짐. **4번 "거부/수정한 것"이 비어 있음** — 이 세션에서 AI 제안에 대한 반박이 0건. 특히 이상 테이블 B안은 권유받자마자 수용. 체크리스트가 경고하는 패턴.

**반복된 오류 패턴**: 전이표를 두 번 틀렸는데 두 번 다 같은 원인 — **종착지 상태를 사건이 움직이게 함**(1차: 다른 종착지로, 2차: 왔던 길로). 근본 원인은 "모든 사건이 상태를 바꿔야 한다"는 전제. 실제로는 12칸 중 7칸이 무전이.
