## 2. 핵심 설계 판단 — "무엇을, 왜"

| 판단 | 근거 한 줄 | 출처 |
|---|---|---|
| 이중장부 **C 방식** (payment/refund에 FK nullable) | polymorphic은 FK 무결성이 없어 기각 | W2D1 |
| `journal` 묶음 **B안** | 불변식을 **사건 단위**로 검증하려고 (W2D5에서 이 선택이 값을 함) | W2D1 §2.2 |
| 셀러별 안분 + **"빼서 구하는" 트릭** | 마지막 셀러를 뺄셈으로 → 균형이 *검사*가 아니라 **구조**로 성립 | W2D2 §2, W2D5 §3 |
| Σ차변==Σ대변 **이중방어** | 앱 `assertBalanced`(조기·친절) + DB 지연 트리거(커밋 시점, 우회 불가) | W2D3 |
| 환불 상태 **파생**(저장 안 함) | 저장하면 진실이 둘로 갈라짐 (W1D3 Redis 폐기와 같은 논리) | W2D4 §1 |
| 가드 **분업** | 앱=자격(PENDING/UNKNOWN), SQL=금액(affected rows가 곧 판정) | W2D4 §3 |
| 역분개 호출 자리: 결제≠환불 | 결제는 멱등, 환불은 **1:1 대응**(같은 금액 2번=진짜 2건) | W2D5 §5 |
| `RefundOutcome` sealed (점검 A) | nullable 규율 대신 **타입으로 벽** — Rejected가 성공을 담는 것 자체가 불가능 | 점검일 A |

## 3. 검증한 것 vs 못한 것

**✅ 실측으로 검증**
- 자동 분개(셀러별 장부), Σ균형 DB 제약, 환불 가드 + 파생 라벨
- **반올림 `.5` 경로** — 3일 묵은 이월을 닫음 (10,000+10,000에 5,001 → 안분 [2501, 2500])
- **부분환불 3회** 불변식 — 전체합(Σ차변==Σ대변) + **사건 단위**(journal별 균형) 둘 다
- 음성대조군: 뺄셈 off → 정확히 2건 빨간불(5건은 그대로 통과 = 나눠떨어지는 fixture가 3일간 버그를 숨긴 이유)
- 점검일: 환불 엔드포인트 5갈래 HTTP 매핑, bootRun 관통(장부3줄→역분개2줄), Kafka 브로커 기동

**⬜ 못한 것 → W3 이월**
| 이월 | 승격/해소 트리거 |
|---|---|
| 환불 동시성 × **역분개 journal 수** 미검증 | `RefundConcurrencyTest`에 ACCEPTED 4 → journal 4 단언 (점검 E) |
| W2D4 동시성 음성대조군 **실패 모드 미기록** | red-light 규약 첫 적용 (점검 D) |
| 비례 안분은 **추정** | W3D4 대사에서 셀러 불일치 잡히면 품목단위(B)로 승격 |
| 파생 라벨 A1 → **A2**(`GENERATED STORED`) | W3D3/D4가 이 라벨로 SQL 필터 걸면 |
| 마지막 몫 음수 · `refund.journal_id` UNIQUE 위반 경로 | 방어는 넣음, 발동 실측 못함 |

## 4. 반복된 패턴 (회고에서 뽑을 결)

- **"규율이 아니라 어길 수 없게"** — append-only 생성자 강제(`Refund.journal`), sealed로 벽(`RefundOutcome`). W1과 같은 형태가 3주 연속.
- **"검사보다 구조"** — `assertBalanced`(검사)보다 뺄셈(구조): 입력과 무관하게 균형. 증명 대상이 "모든 입력"에서 "코드 한 줄의 형태"로 줄어듦.
- **음성대조군 순서 교정** — W2D5는 회귀 전에 실패 메시지를 먼저 뽑음 (W2D4에서 결과 XML이 덮여 실패 모드를 못 남긴 실수 교정).
- **압축한 날 규율 붕괴 전례** — 7/21 D2+D3 압축 → `DROP TRIGGER` 잔류 사고. (W3 리스크로 기록)
